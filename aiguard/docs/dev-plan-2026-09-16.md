## 三、决策点（✅ 已于 2026-09-16 全部拍板）

1. ✅ **建议 1（内网上游）保持批次 4**（第 5–6 周）不前移：内网缺口是关键需求但批次 1–2 的止血与数据闭环优先级更高。
2. ✅ **接受误报 P1 整体后移一个里程碑**（三层豁免 M2→第 7 周、样本回流/评估集 M3→第 8–11 周）：让方案 1 的标签数据先攒 4 周，种子质量优先。
3. ✅ **建议 13 的 B 路打扰级别**：「未聚焦→系统通知、已聚焦→UI 横幅」（对通知克制规则唯一有意例外）。
4. ✅ **第二批规则**（座机/车牌/MAC/IBAN/统一社会信用代码）：待批次 2 上线后按 `fp_stats()` 真实频率数据再决定投入。

## 四、实施陷阱清单（写码前必读，两份报告结论合并）

1. 新增内置规则时 `default_rule_specs()` 与 `preset_table` 三档条目数**精确一致**，否则存量用户档位被 `preset_of_specs`（detector.rs:289）误判 custom；先跑 detector.rs:583-625 单测。
2. 任何前端新 UI：新 t() 键必须进 `src/i18n-dict-ui.ts`（含拼接里的裸冒号/括号），`npm run i18n:check` 校验；拆分 App.tsx 前脚本必须已递归化。
3. 明文直通分支只对用户**显式配置**的内网 host 放行，不得扩大默认接管面；PAC 对 IP 字面量的限制在 UI 如实说明。
4. 隐私红线：样本回流只有字符类别指纹 + 哈希 + 长度分桶；轮换提醒只有条目名/时间/次数；日志/通知/托盘一律不落原文。
5. 依赖零新增：argon2（便携/策略包加密）、git CLI（同步通道，系统命令非 crate）、criterion（仅 dev-dependencies）之外不再引入任何生产依赖。
6. Block 降级语义要在文档与 UI 写清：「Block 只对高置信命中生效」，真实银行卡号单次出现会被降级为 Mask，属可接受权衡。
7. `req_ctx` 正文 10 分钟 `wipe_string` 与 evidence 只留哈希是隐私优点，不要为了「更好归因」破坏它；样本回流走指纹通道。
8. hudsucker 注释漂移（proxy.rs 头注释 0.20 vs Cargo.toml 0.21）与 hyper/rustls 旧栈升级**单列任务**，不与任何功能批次混做。
