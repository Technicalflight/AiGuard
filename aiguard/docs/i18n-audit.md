# 多语言（i18n）审计记录

> 本文记录 aiguard 中英双语能力的架构、已修复的六类漏译根因、三层防线的用法，
> 以及**有意不翻译**的清单。目的是让「英文界面里又冒出中文」这类问题不必从零再查一遍。

## 一、架构：以中文原文为键

界面语言的键就是**中文原文本身**（`DICT[zh] = en`），查不到时回退中文。
设计取舍：宁可露出中文，也不要错译——回退中文是「看得见的缺陷」，错译是「看不见的事故」。

三本词典合并成一张表（`src/i18n.ts`）：

```ts
const DICT = { ...BACKEND_DICT, ...RUNTIME_DICT, ...UI_DICT };
```

| 词典 | 文件 | 来源 | 当前条数 |
|---|---|---|---|
| `UI_DICT` | `src/i18n-dict-ui.ts` | 前端 `t()` 调用点（由抽取器机械生成） | 453 |
| `BACKEND_DICT` | `src/i18n-dict-backend.ts` | Rust 源码字面量 | 274 |
| `RUNTIME_DICT` | `src/i18n-dict-runtime.ts` | 运行期产生的中文（Windows 系统错误原文等），**手工维护** | 14 |

两条查询路径：

- **`t(key)`** —— 前端自有文案，**精确查表**。
- **`tb(text)`** —— 后端流进来的中文诊断。按 精确 → `{}` 规则 → 长片段替换 三级尝试。

两条容易踩的机制：

1. **`{}` 规则是整串锚定的**。`buildRules()` 把含 `{}` 的条目编译成 `^...$` 正则，
   所以 `"已在「{}」中找到本应用 CA"` 这类模板**夹在拼接串里永远匹配不上**。
   → 拼接处必须**逐段**包 `tb()`，不能整串传。
2. **长片段替换只收 ≥4 个汉字、且不含占位符的条目**（防误伤）。
   所以普通条目能被外层容器的 `tb()` 顺带救回，`{}` 模板不能——这是第 1 点的成因。

**判定「这段需要翻译吗」的正则必须包含中文/全角标点**，不能只写 `[\u4e00-\u9fff]`：

```ts
const HAS_CJK =
  /[\u4e00-\u9fff\u3000-\u303f\ufe30-\ufe4f\uff01-\uff0f\uff1a-\uff20\uff3b-\uff40\uff5b-\uff65]/;
```

只写汉字区会漏掉 `。，、（）「」`——它们落在 U+3000-U+303F / U+FF00-U+FFEF。
真实踩过：`}。${detail}` 让英文界面渲染出 `...administrators。Current user ...`。

## 二、已修复的六类根因

| # | 根因 | 表现 | 修复 |
|---|---|---|---|
| 1 | 抽取器只扫 `src-tauri/src`，漏了 `core/src` | 7 个信号名/描述定义在 `core/src/audit.rs`，整块露中文 | `scripts/rust_scan.mjs` 统一扫描口径，`RUST_ROOTS` 含两个 crate |
| 2 | Rust 词法误判字符字面量 | `stripComments` 把 `'"'` 里的双引号当字符串起点 → 506 处「字符串跨行」假象，导致漏抽 | 正确识别 `'\n'`/`'\''`/`'\u{...}'`，并区分生命周期 `&'a str` |
| 3 | 运行期产生的中文无词典归属 | Windows 系统错误原文不在任何源码字面量里 | 新建 `RUNTIME_DICT`（开放集合，覆盖不到时保持原样是预期行为） |
| 4 | 跨进程命名漂移 | `i18n.rs` 的 `SIGNAL_EN` 与前端词典不一致，且措辞违反命名规范 | 对齐 `core/src/audit.rs` 的 `SIGNAL_CATALOG`，自检新增对账节 |
| 5 | 信息面不在 React 渲染范围内 | 原生窗口标题、`document.title`、`<html lang>` 永远停在硬编码值 | `sync_window_title()` + `syncDocumentLocale()`；**必须在 `applyLang` 提前返回之前调用** |
| 6 | 渲染处漏包 `tb()` + 中文标点盲区 | 词典 100% 有译文、构建全绿，只有切英文肉眼才看得见（共出现 10 次） | 补 `tb()`；扩 CJK 正则；新增自检规则 1c / 1d |

第 5 类的细节值得单独记一笔：`applyLang` 里 `if (next === current) return;` 会**吃掉首次加载
这条路径**（后端回传的语言正好等于默认值 zh），导致 `document.title` / `<html lang>` 永远不更新。
同步调用必须放在提前返回**之前**。

## 三、三层防线

三层互补，缺一层就有漏网之鱼。

```bash
npm run i18n:extract   # ① 机械包装：把中文字面量包成 t("...")，抽取/合并词典
npm run i18n:check     # ② 静态自检：4 类规则，秒级
npm run i18n:locale    # ③a 原生属性：document.title / <html lang>（stub DOM）
npm run i18n:e2e       # ③b 端到端：真浏览器逐界面扫描（需 dev server 在跑）
```

### ① 抽取器 `scripts/i18n_extract.mjs`

用 TypeScript 编译器 API 遍历 AST，把中文字面量包成 `t("...")`。
`readExisting()` 保留已有译文，所以可重复运行。改完代码重跑即可。

### ② 静态自检 `scripts/i18n_check.mjs`

四类规则：

- **缺失键** —— `t()` 调用点里的键不在词典中
- **孤儿键** —— 词典里有、但没有调用点（通常是漏包 `t()` 的信号）
- **1c 未包中文** —— 前端文件里未包 `t()/tf()/tb()` 的中文字面量（含标点）
- **1d 后端中文字段裸渲染** —— 见下

1d 的判据是**数据驱动**的：`src/api.ts` 的 MOCK 就是「后端产出的样本」，所以
「MOCK 里值含中文的字段名」== 「运行时可能带中文的字段名」。把这些字段在 `App.tsx`
的 JSX 表达式渲染点找出来，排除已包 `t()/tf()/tb()` 的。

1c 只能查字面量，1d 专门查「词典里 100% 有译文、调用点全绿、构建全绿，只有切英文
肉眼才看得见」那一类。精度靠三个排除函数（表单绑定 / 条件判断 / 方法接收者）
加 `RAW_FIELD_ALLOW` 白名单压到零误报。

### ③a 原生属性 `scripts/i18n_locale_check.mjs`

`document.title` 与 `<html lang>` 不在 React 渲染树里，`innerText` 扫不到；
而它们在**浏览器预览里永远走不到「首屏就是英文」这条路径**（预览的 `get_language`
是常量 MOCK = zh），所以 e2e 也覆盖不到。只能把 `i18n.ts` 真打一份包，在 stub DOM 上跑。

> ⚠ 该脚本的起始状态**故意设成错误值**。若起始值就是期望值，「同步跑过了」和
> 「同步压根没跑」结果一样，断言是空的。第一版就是这么写的，等于没测。

### ③b 端到端 `scripts/i18n_e2e.mjs`

把真实界面切到英文，逐个界面扫 `document.body.innerText` 里残留的汉字。
这是唯一能发现「运行时才出现的中文」的手段。

覆盖 **14 个界面**：6 个导航页 + 5 个弹窗 + 向导 3 屏。

三类断言：

1. **残留中文** —— 逐界面扫汉字（含折叠块，扫前 `details.open = true`）
2. **数据面非空** —— 请求页 / 规则页 / 审计页各 ≥1 行
3. **原生面** —— `document.title` 无中文、`<html lang> === "en"`

> 为什么 i18n 扫描脚本要管「有没有数据」：浏览器预览的数据是常量 MOCK，
> 任何「本该有数据却渲染成空态」都是真缺陷——它会**把 i18n 覆盖盲区藏起来**。
> 真实踩过：`listRequestsPage` 的 MOCK 分支只判 `action` 的真值，而 `RequestsPage`
> 的默认筛选值就是 `"all"`（真值），于是 `"all"` 被当成真过滤器、7 条 MOCK 日志
> 一条都匹配不上，「全部」页恒为空表 → 详情弹窗没有可点的行 → **那一整块界面从未被扫到**。
> 所以：页面非空 = 弹窗可达 = i18n 覆盖完整。三者是同一条链。

`i18n_e2e.mjs` 依赖 Playwright，未列入 `devDependencies`（体积大、按需使用）：

```bash
npm i -D playwright && npx playwright install chromium
# 或复用已有的 Playwright 安装：
NODE_PATH=/path/to/node_modules npm run i18n:e2e
# Playwright 自带浏览器版本对不上时：
AIGUARD_CHROMIUM=/path/to/chrome npm run i18n:e2e
```

## 四、有意不翻译的内容

以下中文在英文模式下**保持原样是正确行为**，不是漏译。e2e 的 `ALLOW` 白名单与此对应：

| 内容 | 理由 |
|---|---|
| `简体中文` | 语言自称：中文在语言列表里永远写作「简体中文」 |
| 用户自定义规则的正则原文（如 `阿尔法计划\|贝塔计划`） | 用户配置的**语义**，翻译它等于改掉用户配置 |
| 用户给规则起的 `name` | 用户数据。但内置规则名要翻——两者同字段，所以走 `tb()`：有译文就翻，没有就原样 |

## 五、命名规范（硬性要求）

- **禁止编号体系**：不用 `S1` / `G1` / `D1` 这类代号做展示名。
- **展示名必须原创**，且达意：报错泄密 / 模型偷换 / 复读篡改 / 流式异常 / 响应夹带 /
  记忆残留 / 高危指令。
- **禁止「主动探针」/「canary」/「金丝雀」**，统一叫「主动核查」「追踪标记」。

## 六、待决策（非缺陷）

1. **`tauri.conf.json` 的 `productName: "AI 安全卫士"`** —— 目前不随语言切换。
   它会进安装包名 / 开始菜单 / 可执行文件名，跟随语言意味着构建产物随语言分叉。
   倾向：**保持不切**，因为安装包名属于产品标识而非界面文案。
2. **`.gitattributes`** —— 仓库纯 Windows，每次提交有大量 CRLF 警告。补一个
   `* text=auto eol=lf` 可以消掉，但会让历史文件的换行行为变化一次。
